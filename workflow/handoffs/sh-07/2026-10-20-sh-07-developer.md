## Decisions and assumptions

- shadcn CLI used: `shadcn@4.22.1` (installed on demand via `npx shadcn@latest`), `init -d --yes` then `add button input label textarea select card badge table alert dialog dropdown-menu separator skeleton sidebar sheet tooltip avatar --yes`. Package additions: `@base-ui/react`, `class-variance-authority`, `cn`, `lucide-react`, `shadcn`, `tw-animate-css` (dependencies); no new devDependencies. Generated files: `components.json`, `src/lib/utils.ts` (`cn()`), `src/hooks/use-mobile.ts`, and 17 files under `src/components/ui/`.
- Dark mode: rewrote the generated `globals.css` to drop the class-based `@custom-variant dark (&:is(.dark *))` and the `.dark {}` selector shadcn's CLI defaults to, replacing it with `@media (prefers-color-scheme: dark) { :root { ... } }` — automatic, OS-driven, no `.dark` class ever added, per the approved spec (`SH-07-R3`).
- Accent colour: set `--primary`/`--sidebar-primary`/`--ring` (light and dark) to one blue `oklch(...)` accent on an otherwise neutral/grey base-color ("neutral") palette; all other shadcn semantic tokens (destructive, muted, card, border, etc.) kept as generated.
- Font: shadcn's own `init` already wired `next/font/google`'s `Geist` with `variable: "--font-sans"` into `src/app/layout.tsx`; removed a leftover unlayered `body { font-family: system-ui, sans-serif }` rule in `globals.css` that would otherwise have won the cascade over the kit's `font-sans` utility and masked the Geist font. Self-hosted, confirmed by a successful `next build` (no runtime font request).
- Sidebar: `RoleShell`'s exported name/props (`{ user, children }`) unchanged; internals replaced with `SidebarProvider` > `AppSidebar` (new) + `SidebarInset` (header + `main`). Nav items centralised in `src/components/app-nav.ts` (`NAV_ITEMS` keyed by `Role`), read by `AppSidebar` from the server-resolved `user.role` only. Admin nav includes a `Courses -> /admin/courses` link per the brief, ahead of that route landing on another branch. Collapse breakpoint is the kit's built-in `768px`/`md` (confirmed in `src/hooks/use-mobile.ts`): below it the sidebar renders as a `Sheet` behind a keyboard-operable `SidebarTrigger` ("Toggle Sidebar"); at/above it, a persistent column.
- Wrapped the sidebar's nav list in a `<nav aria-label="{Role} navigation">` (not present in the generated kit) so it is a real landmark — needed for both accessibility and the new e2e role-isolation checks.
- `next.config.ts`: added `allowedDevOrigins: ["127.0.0.1"]`. Found while writing `tests/e2e/ui-shell.spec.ts`: Next 16's dev-only cross-origin guard was silently blocking the client JS bundle for every `tests/e2e/*.playwright.config.ts` dev server browsed via `127.0.0.1` (all of them use that host), so **no client component ever hydrated** — forms still "worked" because Next Server Actions degrade gracefully to plain POSTs, masking the breakage until a test needed real client state (the sidebar toggle). Dev-only setting; verified `next build`/production output is unaffected.
- `src/components/ui/sidebar.tsx`: removed the generated `document.cookie = "sidebar_state=...`" persistence (and now-unused `SIDEBAR_COOKIE_NAME`/`SIDEBAR_COOKIE_MAX_AGE` constants) — required by `SH-07-R7`/`AC10` ("no new... cookie write"); nothing in this app reads that cookie back, so removing it has no other effect.
- `src/hooks/use-mobile.ts`: rewrote the generated effect-based implementation (which failed `npm run lint`'s `react-hooks/set-state-in-effect` rule) to use `useSyncExternalStore`; same public API (`useIsMobile(): boolean`) and behavior, SSR-safe.
- Native `<select>` elements kept native (not swapped for shadcn's `<Select>`), styled with the kit's own border/background/ring Tailwind tokens by hand — see unresolved-issues list for the reasoning (GET-form serialization and `getByRole("combobox")`/keyboard semantics risk for a presentation-only task).
- `Button`-kit gotcha: Base UI's `Button` defaults to `type="button"` (unlike a native `<button>`, which defaults to `type="submit"`); audited and added explicit `type="submit"` everywhere a native-default submit button was being relied on (`slot-form.tsx`'s "Create slot", `request-card.tsx`'s "Approve"/"Reject").
- Presentational selector changes (justified, no accessible-name/role/test-query change): none required — every `getByRole`/`getByLabel`/`role="status"`/`role="alert"` element an existing test queries by kept its exact tag-or-role, text, and attributes. Where a heading (e.g. "Sign in", "My bookings") coincided with a place I could have used the kit's `CardTitle`, I deliberately kept a real `<h1>`/`<h2>` instead, since `CardTitle` renders a `<div>` with no heading role.
