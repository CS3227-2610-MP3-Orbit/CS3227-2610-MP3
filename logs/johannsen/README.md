# Johannsen's development logs

These logs summarise the prompts and interactions behind Johannsen's part of the project: the
Administrator role (ADM-01 to ADM-04), the shared change-password and UI work (SH-06, SH-07), and the
team infrastructure (repository, CI/CD, deployment, agent setup, reviews and releases).

## How the work was done

- **Tool:** Claude Code (Claude Opus), in one long coordinator session from 17 to 22 October 2026.
  The session ran out of context and was automatically summarised five times; the transcript and
  those summaries are the source for these logs.
- **Agents:** for each feature the coordinator session started the project's role agents from
  `.claude/agents/` (`requirements-architect`, `developer`, `tester-verifier`,
  `security-reviewer`), which load their instructions from `.codex/agents/*.toml`. Child agents
  cannot start further agents. Their handoff notes are in `workflow/handoffs/<feature>/`.
- **Human gates:** Johannsen approved every specification, decided every open question, and did
  every `git push`. The agents were not allowed to push, deploy, or read `.env` files.

## How to read each section

Each section follows the same order:

1. **Prompts:** what Johannsen typed, quoted as typed (typos kept). Long pasted text is
   summarised in square brackets.
2. **What the agent did:** what Claude Code and its role agents produced.
3. **What I checked or changed:** where Johannsen questioned, corrected, narrowed or overruled the
   agent.
4. **Outcome:** commits, pull requests and test results that can be checked.

The summaries were generated by Claude Code from the session transcript and the repository. Each
section ends with a verification line. Johannsen replaces it with "Verified by Johannsen on
<date>" after checking the section against the cited commits and pull requests.

## Standing rules given to the agent

These were given once and applied for the rest of the project:

- "do not pr or push messages as claude for future, remove them. i just want to see my name for the
  github contribution" (19 Oct). No Claude co-author lines or "Generated with Claude Code" in
  commits, pull requests, issues or reviews.
- The agent never reads `.env.secrets`, `.env.test-accounts` or any `.env*` file, and never prints a
  key. Local keys are loaded only through `tests/integration/local-supabase-env.mjs`, which exports
  them without printing.
- The agent never runs `git push`, `vercel deploy`, `vercel env`, `supabase db push` or
  `supabase link`; Johannsen pushes. These are also denied in `.claude/settings.json`.
- Screenshots for checking the UI: "(Do not put this in git or in this folder)".
- Ask before anything destructive or visible to others.
